# proof_motif_v1：单棵证明的跨世界结构签名

- 日期／责任方：2026-09-24，Codex；对应 [D32](decisions.md#d32单棵证明的有界参考-motif-键)与 [T0014](handoffs/T0014-proof-motif.md)。2026-09-25实现已通过第4轮验收并提交`f5ef96f`；本表示契约不变。
- 依据：[proof_identity_v1 §4](proof_identity_v1.md#4-motif-的后续约束)、研究计划 §5.2。E0 `e0_v2`、E1 `e1_v3`、同世界证明身份和模型输入白名单不变。

## 1. 等价关系与边界

输入为给定 query 的一棵有限、合法、完整出现树，接受范围继承 T0012：无共享引用、无无关步骤，允许合法的有限循环规则证明。正式 E0 世界仍须无环。

在同世界证明身份允许的局部变量双射、来源／步骤重编号和 schema 前提槽位与子树联合交换之外，本层再消除**整棵树一致**的关系名双射与实体名双射。关系与实体是独立命名空间；局部 schema 变量仍每节点单独作用域。不把原字符串大小写作为结构特征，但改名必须一致且一一对应，不能随意将两个不同符号合并。

保留：树形、重复发生、每节点 ground 结论与完整 clause schema、所有参数位置、常量／变量类别、变量相等关系、全树关系与实体的相等／共享关系。扫描范围只含此树用到的内容，未引用的世界条款不参与编号。

例如，经 b 与经 d 的两条 JOIN 支持可以有同一 motif，却仍是两条同世界证明。不能拿 motif 数替代 T0013 的唯一性判据。孤立 `p(a,b)` 与 `p(b,a)`（a≠b）也可经全局实体交换成为同一 motif；方向应由 schema 中的参数对应验证。COPY 与 INV、两次 COPY 与两次 INV，即使全部实例化参数相同，也不合并。

本版只定义整树键。不决定内部子结构的截取／边界绑定、motif 保留清单、训练／测试划分配额或正式数据准入，不宣称已无泄漏。键仅为离线审计材料。

## 2. 输出格式

```text
Key = ("proof_motif_v1", (Header, ...))
Header = (Ground, HeadSchema, BodySchemas)
Ground = (relation_id, entity_id_0, entity_id_1)
SchemaAtom = (relation_id, Term_0, Term_1)
Term = ("c", entity_id) | ("v", local_variable_id)
BodySchemas = (SchemaAtom, ...)  # 长度为 0、1、2
```

所有容器为真实 tuple，所有编号为非 bool 的真实 int，且非负；仅版本和 c/v 标签为 str。流为根在前的前序，每节点子树数等于 `len(BodySchemas)`，因此可唯一恢复树。输出嵌套深度不随树高增长，可以比较和 hash；不是压缩摘要或 world 指纹。

给定一种完整槽位方向后，按该方向的根前序扫描，每节点顺序固定为：

1. ground 的关系、第一实体、第二实体；
2. schema head 的关系、第一项、第二项；
3. 已定序 body 中每个 atom 的关系、第一项、第二项；
4. 按同一 body 顺序访问子树。

关系／实体各有一张全树表，各自从 0 首现编号；schema 常量与 ground 实体共用实体表。每节点变量表重置为 0，按 head→当前有序 body 首现编号，变量不消耗实体编号。不同候选之间所有表重新初始化。

## 3. 有界参考算法

1. 原对象、原 `max_steps` 恰一次交给 T0012 `canonical_proof_key`。其错误原实例传播，不重复 verifier，不先扫描或转换原输入。
2. T0012 成功后校验 `max_orientations`（简称 O）：`type(O) is int and O > 0`。因此已有输入／单树预算错误先于 O 错误。非法 O 抛 `LogicValidationError("motif.max_orientations must be a non-bool positive integer; got TYPE")`，TYPE 仅为类型名，不回显值。
3. 从 T0012 平坦 header 流恢复 children：逆序遍历节点，对 arity 次依次弹出栈顶作为有序 children，然后压入本节点；弹出的 children 不再反转。信任内部返回格式，不新增通用序列解析／修复 API。
4. 所有二槽**出现节点**按原前序分配稠密位号 `0..B-1`；不能用节点索引代替位号。即使两槽和子树完全相同，也各计一个二槽节点。
5. 候选数固定为 `2**B`。构造候选前用受 O 约束的逐次倍增预检：若当前值 `> O // 2`，下一次倍增就超限。超限抛 `MotifLimitError("motif.max_orientations insufficient for complete canonicalization")`，不生成或返回部分键。B=0 需 1，B=1 需 2，B=3 需 8；相同候选不抵扣预算。
6. 枚举整数 `0..2**B-1` 的方向位。每个被翻转的节点同时逆序 schema body 和对应 children。显式栈做前序遍历，按 §2 重新编码；T0012 已给的变量编号此时只作为变量身份，必须按新方向重新首现编号。
7. 所有完整候选中按 Python tuple 字典序取最小，返回完整键。仅保留当前候选和 best；不构建每节点完整子树流，不用递归、持久缓存或符号全排列。

为何成立：固定有序树的完整首现编码恰好消除全局双射；枚举每个二槽的联合方向覆盖允许的无序表示。T0012 的原排序只是起点，重新枚举两种方向不会丢失表示。反过来，相等完整键确定相同树、全局符号对应和每节点的局部变量对应。

新增枚举阶段耗时为 O(n·2^B)、工作空间 O(n)，n 为发生节点数；此处复杂度不包含 T0012 已有验证／规范化成本，也不把 Python 大整数运算视为任意规模常数。O 默认 100000，只约束方向候选数，不保证固定墙钟耗时。较大树可能明确拒绝；此时结果是未完成审计，不是 motif 不同。以后若优化算法，须另行证明完整性和预算语义，不能在本任务中剪枝、抽样或提前返回。

## 4. 手算完整键

单事实 `p(a,b)`，a≠b：

```python
("proof_motif_v1", (
    ((0, 0, 1), (0, ("c", 0), ("c", 1)), ()),
))
```

事实 `p(a,b)` ＋ COPY `p(?x,?y)→q(?x,?y)` 得 `q(a,b)`：

```python
("proof_motif_v1", (
    ((0, 0, 1), (0, ("v", 0), ("v", 1)), ((1, ("v", 0), ("v", 1)),)),
    ((1, 0, 1), (1, ("c", 0), ("c", 1)), ()),
))
```

事实 `p(a,b),q(b,c)` ＋ JOIN `p(?x,?y),q(?y,?z)→r(?x,?z)` 得 `r(a,c)`：

```python
("proof_motif_v1", (
    ((0, 0, 1), (0, ("v", 0), ("v", 1)),
     ((1, ("v", 0), ("v", 2)), (2, ("v", 2), ("v", 1)))),
    ((1, 0, 2), (1, ("c", 0), ("c", 2)), ()),
    ((2, 2, 1), (2, ("c", 2), ("c", 1)), ()),
))
```

JOIN 的反方向候选在第一个 body atom 的第一个变量位置为 v2，而上述为 v0，故上述较小。其它共享、退化、长链和接口例见任务契约；不用目标函数生成这些期望。
