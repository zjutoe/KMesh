## D18：逻辑类型的实现约定

- 日期／责任方：2026-09-15，Codex；关联 [T0003](handoffs/T0003-logic-types.md)。这是正向 Horn 协议的工程表示澄清，不改变实验任务或研究协议版本。
- 统一使用不可变、可哈希的 `Atom(pred, args)` 与 `Clause(body, head)`；事实是空 body 的 Clause。元数据、角色、模板标签、证明及 ID 不混入这两个内容类型。
- 谓词/常量标识符采用 ASCII `[A-Za-z][A-Za-z0-9_]*` 整串匹配；变量采用 `?` 前缀，之后使用同样标识符。`x` 与 `?x` 不同，大小写保持；无隐式转换/修剪，不硬锁 `rN/eN/?x/?y/?z`。这是符号拼写约定，后续词表大小、世界数量上限和 token 长度仍须在相应边界校验。
- Atom 是二元的，Clause 允许 0–2 个前提且 head 变量必须在本 clause 的 body 出现；空前提的事实必须 ground。这些语义来自计划 §4.1，本任务不新增否定、函数符号或全局变量绑定。
- 静态类型可表示满足上述条件的正向 Horn clause；E0 允许的生成模板、世界 DAG、词表成员/数量、ground query、重复数据、family/证明审计由后续任务明确实现。构造成功不等于世界通过 E0 审计。
- Python 对象相等按结构和顺序；不自动重排前提、交换参数、去重或改名。前提交换/变量重命名的逻辑等价与 motif 规范化不由本层判断；普通 Python hash 也不充作持久内容标识。
- 若后续改变逻辑元数、前提数量、ground/range restriction、E0 模板/递归许可、模型可见字段或划分所用等价关系，须先由 Codex 更新相应研究协议并记录影响；Pi 不自行扩大或收窄。

## D19：参考闭包的求解与预算约定

- 日期／责任方：2026-09-15，Codex；关联 [T0004](handoffs/T0004-reference-closure.md)。落实计划 §4.5 的枚举绑定参考路径，不改变研究协议版本，也不声称实现已完成。
- 初始 API 为 `reference_closure(tuple[Clause, ...], *, max_rule_evaluations=100_000) -> frozenset[Atom]`；只接收内容类型，返回包含原始事实的完整 ground 闭包。World/Proof/ClosureResult 与 CLI 留给后续任务，不预建框架。
- 实体域取全部 clause 的 body/head 常量，每条规则独立枚举局部变量的全体绑定，以上一轮闭包为快照同步迭代到不动点。不从查询补域，不加虚拟实体；仅有规则且无事实不能凭空启动推导。
- 预算累计每个非空规则的候选绑定检查，包括失败绑定、重复规则和最终无新增轮；初始 facts 不计。上限前不能完成则抛 `ReferenceLimitError`，不输出部分闭包。此预算是参考程序执行保护，不是世界语义限制、生成器拒绝标准或正式性能目标。
- 参考版与未来索引主版只共享内容类型/静态校验，不共享匹配、替换、规则应用或闭包算法。主版完成后另以随机小世界交叉验证，保存证明还需要独立 verifier。
- 参考版可用循环规则核验终止性；E0 起始生成世界仍须关系 DAG。求解成功不代表模板、world、family 或证明审计通过，求解器及闭包不得进入模型 forward/predict 或输入。

## D20：索引闭包与小世界交叉验证约定

- 日期／责任方：2026-09-15，Codex；关联 [T0005](handoffs/T0005-indexed-closure.md)。落实计划 §4.5 的第二条求解路径，不改变协议版本。
- 初始 API 为 `indexed_closure(tuple[Clause, ...], *, max_fact_checks=100_000) -> frozenset[Atom]`；每轮索引上一轮 facts，按谓词桶逐前提单向匹配/嵌套 join，同步迭代。只共享内容类型/静态校验，不共享参考版的匹配、替换、规则应用或闭包实现。
- 预算计每次候选 fact 与当前前提/绑定的匹配尝试，包括失败、重复访问/规则与最后无新增轮；索引和初始 facts 不计。无候选为 0，超限抛 IndexedLimitError，不返回部分闭包。它与参考版的绑定枚举计数不同，不是公平性能/总成本指标。
- 正确性先由手算闭包/预算/绑定隔离测试检查，再以 seed `20260915` 的 64 个小型合成世界比较完整闭包；世界生成只在测试文件内，偶数编号加入隔离的两步推导链，避免全是事实回传。一般 Horn/循环测试不放宽正式 E0 模板和 DAG。
- World/Proof/RuleEngine 封装、独立 proof verifier、正式生成器与数据审计另行拆分。双求解器一致只覆盖规定小世界，不能替代研究有效性、完整数据审计或科学命题验证。


## D21：给定证明的独立核验

- 日期／责任方：2026-09-16，Codex；关联 [T0006](handoffs/T0006-proof-verifier.md)。落实计划 §4.5/§15.1 对独立 proof verifier 的要求，是工程表示澄清，不改变 E0 `e0_v2` 或研究协议。
- 采用离线内存表示 `ProofStep(clause_index, premise_steps, conclusion)`：冻结步骤、ground 结论、指向当前 clauses 顺序的索引和更早 proof 步骤的有序引用。证明为 tuple，最后结论对应 query；不加入绑定表、标签/深度/ID，不把位置索引当持久 patch ID 或模型特征。
- `verify_proof(clauses, query, proof, *, max_steps=10_000) -> bool` 独立核对每步的原始事实/规则、前提谓词/参数与局部变量替换。只共享内容类型与标准库，不导入/调用两条 solver 或共用其匹配/替换代码，不自动搜索/补全证明。
- 构造/入口结构错误抛 LogicValidationError；结构正确而给定证据无效返回 False。总步骤数超限抛 ProofLimitError，不能返回 False 或部分通过。入口先校验 clauses/query/proof 外层/预算，再检查长度，限内先查全体成员类型，再查逻辑；细节和原因片段固定在交接中。
- 允许合法无关步骤、重复步骤、重复引用同一步、由事实支撑的循环规则有限展开；全体提供步骤都要验证，引用严格指向更早步骤。长度预算计入所有步骤，不等同最短推理深度。
- True 只证明所给证据成立，不说明最短/唯一/不存在其他路径；False 不能作不可推出的负标签。生成/枚举、最短深度、motif 与 world 审计、持久格式另拆任务；proof 与中间结论不得进入模型输入/预测。

## D25：E0 关系依赖无环检查

- 日期／责任方：2026-09-17，Codex；关联 [T0007](handoffs/T0007-relation-dag.md)。落实计划 §4.1 的起始关系 DAG，是已有约束的工程接口澄清，不改变 E0 `e0_v2`，不代表实现完成。
- `relation_topological_order(tuple[Clause, ...]) -> tuple[str, ...]` 将全部 head/body 谓词作为顶点，每个前提谓词向 head 谓词连有向边，重复边去重。事实只贡献顶点；无事实、不可达或 ground 条件不匹配不能豁免循环检查。
- 先检查全部输入结构，再使用迭代拓扑排序；每步选择当前零入度谓词中字典序最小者，输出所有不同谓词。空输入返回空 tuple；循环抛 LogicValidationError，不返回部分顺序。不求具体环，不引入模板／大小限制或通用图框架。
- 重复 clause 可通过本项检查；重复数据、模板、词表／规模、证明唯一性、motif／family 与泄漏审计后续另做。既有求解器／给定证明验证器仍可处理其原契约允许的循环输入，不接入该限制。
- 关系 DAG 与用于神经读取的 patch 相似图不同。拓扑顺序／rank 仅作离线审计信息，不进入模型输入、embedding 或路由，不声称它能预测神经更新后的退化范围。下一步可在已验收 DAG 边界上拆分有限证明枚举，不在本任务合并实现。

## D26：先保存全部直接推导，再展开完整证明

- 日期／责任方：2026-09-17，Codex；关联 [T0008](handoffs/T0008-ground-derivations.md)。落实计划 §4.5／§5.2 有限 proof 枚举的前置接口，不改变 E0 `e0_v2`，尚未实现，不新增模型信息或研究预算。
- `GroundDerivation(clause_index, premises, conclusion)` 保存一次 ground 直接应用；premises 按原 body 位置排列，事实为零前提。index 只是本次输入位置，不是稳定 patch ID；构造仅验证结构，不单独证明语义正确。
- `enumerate_derivations` 先校验参数并调用 T0007 拒绝任意关系环，再按谓词拓扑序、原 clause index、有序候选嵌套遍历返回全部直接应用。所有同结论来源保留；重复 clause 按不同输入位置保留，下游候选仅对 ground Atom 去重。原始 index／前提顺序不定义规范证明身份。
- 两项正整数预算分别计候选匹配次数与输出记录数（含事实）；恰好完成可返回，再需一步则抛 DerivationLimitError，无部分结果。它们是执行保护，不是正式数据生成配额、完整证明数或成本结论。
- 一条直接推导的前提可能各有多种证明，因此直接记录数不等于完整证明数；闭包相等也不证明所有替代来源已保存。T0008 同时核对手算完整应用和小世界闭包。完整证明展开／独立核验、最短深度、规范化／唯一性、motif 与 family 审计后续拆分，不在此直接判唯一或完成 world 审计。

## D27：单查询的原始证明树展开
