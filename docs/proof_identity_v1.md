- 依据：研究计划 §4.4–4.5、§5.2；[D29](decisions.md#d29规范条款键与证明身份分层)。
- 状态：T0011 单 clause 键已验收；[T0012](handoffs/T0012-proof-key.md)交接单棵出现树的证明键，尚未实施。正式数据生成前，仍须验收完整证明身份、唯一性审计、motif 算法、子结构匹配和 split manifest。
- 版本影响：E0 主协议仍为 `e0_v2`；新增审计子协议 `proof_identity_v1`。后续唯一性审计须记录此版本，不得将 T0009 原始树数量直接重标为规范证明数。本次没有生成或重新标记任何研究数据。

## 1. 两种不同问题

**同世界证明身份**回答：给定世界和 query，有多少条实质不同的支持证明？保留世界中实际的谓词、常量、规则内容和支持结构，只消除约定的表示差异。

**跨世界 motif 签名**回答：忽略实体和关系的任意命名后，证明用了怎样的组合结构？它还需消除全树一致的关系／实体双射重命名，供组合保留和泄漏审计使用。不同证明可以有同一 motif，不能以 motif 数判定唯一证明。

例如，同一世界同时有 `p(a,b), q(b,c), p(a,d), q(d,c)` 和 JOIN 规则 `p(?x,?y), q(?y,?z) -> r(?x,?z)`。`r(a,c)` 分别经 b、d 的支持是两条不同证明；它们的结构可以相同。唯一性审计必须识别两条支持。

## 2. 单 clause 内容等价（T0011 实施）

两个合法 Clause 当且仅当能通过以下操作互相变换时，视为同一 clause 内容：

1. 对一个 clause 内的全部变量作一致双射改名；变量作用域不跨 clause。
2. 交换两个 body 槽位；head 不移动，每个 Atom 的两个参数位置不交换。

保持谓词和常量原名、大小写、常量／变量类别、变量相等关系、head/body 身份及 body 多重性。不做逻辑等价判定、规则蕴含化简或重复前提删除。事实、ground 规则、body-only 变量及 T0003 允许的非 E0 模板也有键；键不证明世界合法或满足模板限制。

正反例：

| 输入对 | clause 内容等价？ |
|---|---|
| `p(?x,?y)->q(?x,?y)` 与 `p(?u,?v)->q(?u,?v)` | 是 |
| `p(?x,?y)->q(?x,?y)` 与 `p(?y,?x)->q(?y,?x)` | 是；整体一致改名 |
| JOIN 的两个 body Atom 交换且 head 保持原样 | 是 |
| COPY `p(?x,?y)->q(?x,?y)` 与 INV `p(?x,?y)->q(?y,?x)` | 否；head 与 body 参数对应不同 |
| `p(?x,?y),q(?y,?z)->r(?x,?z)` 与 `p(?x,?u),q(?v,?z)->r(?x,?z)` | 否；共享绑定不同 |
| `p(?x,?y)->q(?x,?y)` 与 `p(?x,?y),p(?x,?y)->q(?x,?y)` | 否；槽位数量不同 |
| `[]->p(a,b)` 与 `[]->p(b,a)`，a≠b | 否 |
| 仅改一个出现位置的实际谓词或常量名，其余位置不变 | 否；本层保留实际符号 |

“保留参数方向”指整个 clause 的对应关系，而不是保留变量拼写。一个孤立 Atom 的 `?x/?y` 改名不应被误当作方向反例。

保留实际符号不等于“任何多处符号改名必然改变键”：对称 clause 的改名结果可能恰好也是合法 body 交换。例如 `p(a,a),p(b,b)->q(c,c)` 同时交换 a/b 后，仍是原 body 的逆序，因此键相同。这不是引入一般实体改名等价。

## 3. 同世界完整证明身份（后续实施）

对象是 T0009 所枚举的、以 query 为根的有限**出现树**；每个前提槽位有一个子树出现。它不等于任意 verifier 可接受的、带无关步骤或共享引用的步骤序列。保持各节点实际 ground 结论、所用 clause 内容和全部后继支持。

两个树节点等价，需要 ground 结论相同，且存在 clause 局部变量双射与 body 槽位置换，使 clause 内容对齐，同时该置换配对的子树逐一等价。事实为无子节点的情形。递归定义不要求实现使用 Python 递归；长链实现另定。

因此：

- 消除 clause 存储位置、重复等价 clause 的来源下标、证明步骤编号及无语义的前提顺序差异；不消除不同实际事实、规则或替代支持路径。
- 重复前提仍保留两个出现；A 与 B 不等价时，`(A,A)` 与 `(A,B)` 不合并。若 clause 的两个槽位确有对称性，联合交换产生的 `(A,B)` 与 `(B,A)` 可以相同。
- 不能先独立规范 clause 再随意排序所有子树。置换必须作用于“schema 前提槽位及其对应子树”这一对；ground 前提偶然相等也不证明 schema 槽位对称。
- 对称 clause 可能有多个最小键映射。T0011 **只返回键、不返回槽位映射**；未来树算法须处理全部有效对齐，不能假定能从该键恢复唯一映射。
- 不比较原始 binding 字典来判不同证明。例如 `p(?x,?z),p(?x,?w)->q(?x,?x)` 的 z=b,w=c 与 z=c,w=b，在联合交换变量／子树后可能等价；不同桥接实体的 JOIN 例仍不等价。

只有枚举完整成功、逐树验证且按该等价关系归并后，才能报告规范证明数。重复 clause 的世界审计仍需另行报告；归并重复表示不等于允许正式数据包含重复 patch。资源不足时为未完成审计，不能报唯一。

### 3.1 T0012 的平坦键实施契约

T0012 只实现给定单树的 `canonical_proof_key(clauses, query, proof, *, max_steps=10_000)`，不实现计数。先调用 T0006 验证给定证据，再要求每个非末步骤恰被引用一次，拒绝共享 DAG 与无关步骤；合法拓扑编号可交错，不要求特定后序存储。合法有限自环规则证明不因世界含环而被拒绝。

输出为 `("proof_key_v1", (Header, ...))`，每个 Header 为 `(GroundKey, ClauseKey)`，GroundKey 保留谓词和两个实际常量，ClauseKey 采用 T0011 的完整 tuple 格式。流为规范前序，节点 arity 由 ClauseKey 的 body 长度恢复；重复出现保留，嵌套深度不随证明深度增长。它不是世界指纹或持久摘要。

每个节点分别考虑原 body／逆序的有序 clause 编码及对应子树；编码不同时选择较小编码并同步配对子树，编码相同时才按子树完整规范前序流选择较小排列。不能只比较子树根 header。具体反例、预算／异常和长链要求见 T0012；同世界身份等价关系本身不变，仍为 `proof_identity_v1`，未重新标记任何数据。

## 4. motif 的后续约束

跨世界抽象需用**全树一致**的关系双射和实体双射；两个命名空间彼此独立，不能逐节点各自改名。保留共享符号关系、局部 schema 变量绑定、参数位置、重复槽位及组合树；COPY/INV 等 schema 差异不能因实例化为相同实体而消失。两次 COPY 与两次 INV 即使端点映射相同，也不因此合并。

此处只冻结与同世界身份的边界。motif 的完整编码、模板退化情形、内部子结构匹配、清单和 split 数量仍须单独交接与审阅，当前不能生成正式 motif 划分或声称无泄漏。Clause 键、证明、支持集、signature 均为审计材料，不自动成为模型可见信息。
